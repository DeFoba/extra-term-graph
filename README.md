# Extra-Term-Graph (Конструирование терминологического графа и анализ научных статей)

Проект представляет собой автоматизированный пайплайн для сбора, обработки и анализа научных статей из журнала **«Онтология проектирования»**. Пайплайн извлекает метаданные и тексты из PDF-файлов, извлекает и оценивает ключевые слова, генерирует реферативные аннотации и строит семантический граф публикаций и терминов с автоматическим экспортом в графовую базу данных **Neo4j (Aura DB)**.

---

## 🚀 Основные возможности
1. **Парсинг архива журнала (`pars_news.py`)**: Автоматический сбор ссылок на выпуски и тома журнала, скачивание полнотекстовых PDF-статей в локальную директорию.
2. **Обработка PDF и построение корпуса (`modules/corpus.py`)**: Извлечение текстов из PDF с фильтрацией колонтитулов, нормализация разметки, склейка переносов слов, а также интеллектуальное разделение статьи на метаданные (название, авторская аннотация, ключевые слова) и основной текст.
3. **Извлечение ключевых слов (`modules/keywords.py`)**:
   - Морфологический анализ и лемматизация на русском языке с помощью `pymorphy3`.
   - Извлечение ключевых слов методами **TF-IDF** и **KeyBERT** (с использованием легковесной семантической модели `mlsa-iai-msu-lab/sci-rus-tiny`).
   - Сравнительная оценка качества извлечения (Exact Match и Soft Match на основе коэффициента Жаккара) относительно авторских ключевых слов.
4. **Реферирование (`modules/summarization.py`)**:
   - Выделение предложений и фильтрация шума.
   - Метод **MMR (Maximal Marginal Relevance)** с весами ключевых слов для генерации сжатого содержания статьи (из 4 предложений).
   - Оценка качества реферирования относительно авторских аннотаций по метрикам **ROUGE-1, ROUGE-2, ROUGE-L** (как на исходных словоформах, так и на лемматизированном тексте).
5. **Графовый анализ и экспорт (`modules/graph.py`)**:
   - Построение связей «Публикация — Публикация» по пересечению ключевых слов (коэффициент Жаккара).
   - Построение семантических связей «Термин — Термин» по близости векторных эмбеддингов предложений.
   - Построение иерархических связей терминов (связь «гипоним-гипероним» на основе вложенности токенов).
   - Экспорт графа в CSV и генерация скрипта импорта Cypher.
   - Автоматическая заливка графа в облачную/локальную базу данных **Neo4j**.

## 📂 Структура проекта

```text
├── articles/                   # Папка со скачанными PDF-статьями (в гите игнорируется)
├── corpus/                     # Сгенерированные JSON-файлы для каждой статьи (в гите игнорируется)
├── graph_export/               # Экспортированные CSV-файлы узлов и связей (в гите игнорируется)
├── modules/                    # Модули пайплайна
│   ├── __init__.py
│   ├── corpus.py               # Предобработка PDF и сбор корпуса
│   ├── keywords.py             # Извлечение и оценка ключевых слов
│   ├── summarization.py        # Реферирование и оценка ROUGE
│   └── graph.py                # Построение графа и интеграция с Neo4j
├── Neo4j-*.txt                 # Конфигурация подключения к Neo4j Aura (в гите игнорируется)
├── pars_news.py                # Парсер архива журнала (скачивание PDF)
├── run_pipeline.py             # Главный оркестратор пайплайна (CLI интерфейс)
├── import_csv.cypher           # Сгенерированный скрипт ручной загрузки CSV в Neo4j
├── corpus.json                 # Сводный индекс метаданных всего корпуса
├── requirements.txt            # Список зависимостей
├── run_full_pipeline.bat       # Windows скрипт для запуска всех шагов
├── run_graph_only.bat          # Windows скрипт для запуска только построения графа
└── run_test_pipeline.bat       # Windows скрипт для быстрого теста пайплайна на лимитированном наборе
```

## 🛠️ Установка и настройка

### 1. Клонирование и установка зависимостей
Убедитесь, что у вас установлен Python 3.10+.
```bash
git clone https://github.com/DeFoba/extra-term-graph.git
cd extra-term-graph
pip install -r requirements.txt
```

### 2. Подключение к Neo4j
Для автоматической загрузки графа в Neo4j (например, Neo4j Aura), создайте в корневой директории файл с именем в формате `Neo4j-XXXX.txt` (где XXXX — любой индентификатор) и следующим содержанием:
```env
NEO4J_URI=neo4j+s://ваш-адрес.databases.neo4j.io
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=ваш-пароль-к-базе-данных
```
*Примечание:* Из соображений безопасности файлы по маске `Neo4j-*.txt` добавлены в `.gitignore` и никогда не попадут в публичный репозиторий.

## 💻 Инструкция по запуску

### Шаг 1. Загрузка статей из журнала
Для того чтобы скачать статьи с официального сайта журнала в папку `articles/`, запустите парсер:
```bash
python pars_news.py
```
После завершения в корне появится папка `articles/` со всеми найденными выпусками PDF.

### Шаг 2. Запуск пайплайна анализа
Вы можете запускать пайплайн целиком или по отдельным шагам с помощью `run_pipeline.py`.

* **Полный цикл анализа и импорт в базу данных:**
  ```bash
  python run_pipeline.py --step all
  ```
  Или запустите файл `run_full_pipeline.bat`.

* **Только парсинг PDF и создание корпуса:**
  ```bash
  python run_pipeline.py --step corpus
  ```

* **Только извлечение и оценка ключевых слов (требуется уже готовый корпус):**
  ```bash
  python run_pipeline.py --step keywords
  ```

* **Только реферирование и оценка ROUGE:**
  ```bash
  python run_pipeline.py --step summarize
  ```

* **Только генерация графа и экспорт/загрузка в Neo4j:**
  ```bash
  python run_pipeline.py --step graph --jaccard_threshold 0.05 --semantic_threshold 0.90
  ```
  Или запустите файл `run_graph_only.bat`.

* **Тестовый запуск на малом количестве статей (например, 5 штук):**
  ```bash
  python run_pipeline.py --step all --max_articles 5
  ```
  Или запустите файл `run_test_pipeline.bat`.

## 📊 Модель данных Neo4j

Пайплайн разворачивает в Neo4j следующую схему:

### Узлы
* `Publication`: Научная статья.
  * Свойства: `id` (имя файла), `title` (название), `annotation` (авторская аннотация), `summary_tfidf` (реферат по TF-IDF), `summary_keybert` (реферат по KeyBERT).
* `Keyword`: Термин (нормализованная лемма).
  * Свойства: `id` (нормализованная лемма), `name` (наиболее частое написание термина с большой буквы).

### Связи
* `(p:Publication)-[:HAS_KEYWORD {method, weight}]->(k:Keyword)`: Статья содержит термин. Свойства: метод извлечения (`author`, `tfidf`, `keybert`) и вес термина.
* `(p1:Publication)-[:SIMILAR_TO {score}]->(p2:Publication)`: Статьи похожи по пересечению терминов (индекс Жаккара).
* `(k1:Keyword)-[:SEMANTICALLY_SIMILAR {score}]->(k2:Keyword)`: Термины семантически близки по векторным представлениям.
* `(k1:Keyword)-[:SUB_TERM_OF]->(k2:Keyword)`: Термин является составной частью более общего термина (например, *«база знаний»* $\rightarrow$ *«знание»*).
